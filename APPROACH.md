# Описание подхода: архитектура сопоставления, обработка ошибок и ограничения

Документ подготовлен для сдачи тестового задания и технического интервью на позицию **AI-разработчик**.

---

## 1. Как устроено сопоставление позиций

В реальной стройке язык мастера и техническая спецификация — это два принципиально разных словаря:
- **В спецификации:** «Фреонопровод медный, марка меди Cu-DHP по EN 12735-1 Д6,35 TEC TUBE cips» (ед. изм.: м)
- **У мастера:** «медь 6-ка 15 м», «шестерка», «фреонка 6»
- **В спецификации:** «Трубка теплоизоляционная для изоляции фреонопроводов из вспененного полиэтилена класс горючести Г1, с толщиной стенки б=9мм, K-FLEX ST Д6,35»
- **У мастера:** «изоляцию на них столько же» (контекстная анафора)

Для решения этой задачи реализован **двухуровневый гибридный конвейер (Hybrid AI + Deterministic Pipeline)**:

```
[Сообщение мастера: голос / текст]
               │
               ▼
   [Whisper Audio Transcriber]
               │
               ▼
┌──────────────────────────────────────────────┐
│  УРОВЕНЬ 1: LLM Reasoning + Coreference     │
│  • Динамическая инъекция каталога (~62 поз.) │
│  • Разрешение ссылок («столько же», «на них»)│
│  • Сопоставление сленга по физическим знач.  │
│  • Детекция интента: отчет или вопрос        │
└──────────────────────┬───────────────────────┘
                       │
                       ▼ (JSON AST)
┌──────────────────────────────────────────────┐
│  УРОВЕНЬ 2: Deterministic Rule Validator     │
│  • Проверка единиц измерения (м, шт, кг)     │
│  • Детекция неоднозначностей (нет диаметра)  │
│  • Проверка остатка по смете (Over-limit)    │
│  • Резервный RapidFuzz/Regex парсер          │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
         [Interactive FSM в Telegram]
      (Подтверждение / Выбор / Запись)
```

### Динамический каталог (без хардкода в коде)
Справочник позиций не зашит в код. При старте или по команде `/reload` сервис `CatalogService` загружает строки напрямую из Google Sheets / Excel:
1. Выделяет разделы («ОВ 3», «ЭМ3»).
2. Определяет техническое наименование, единицы измерения, сметные объемы и стоимость.
3. Автоматически генерирует набор ключевых сленговых токенов (диаметры труб `6.35 -> 6`, сечения кабелей `3х2.5`, типы хомутов `фреон / дренаж`).
4. Рассчитывает актуальный остаток: $\text{Остаток} = \max(0, \text{Объём по смете} - \text{Выполненный объём})$.

### Разрешение контекстных ссылок (Coreference Resolution)
Фраза: _«проложили медь 6-ку 15 м и 9-ку 15 м, изоляцию на них столько же»_:
LLM сохраняет контекст предшествующих сущностей:
- Определяет, что медь 6-ка имеет диаметр Д6,35 (15 м) и медь 9-ка — Д9,52 (15 м).
- Находит в спецификации соответствующие изоляционные трубки К-FLEX с теми же диаметрами (Д6,35 и Д9,52).
- Присваивает каждой изоляционной трубке объем 15 м.

## 2. Поведение в спорных случаях (Неоднозначность)

Согласно требованию ТЗ: **«Если позиция не распознана или подходит сразу несколько вариантов, уточнять у мастера, а не угадывать»**.

Примеры:
1. **«Поставили 10 хомутов»**:
   В спецификации есть две позиции:
   - Ряд 43: «Хомут для крепления дренажа М8 25мм»
   - Ряд 44: «Хомут для крепления фреонопровода М8 32 мм»
   Бот не пытается угадать случайный хомут. Он переводит пользователя в состояние `clarifying_ambiguous` и отправляет клавиатуру:
   ```
   ❓ Требуется уточнение по позиции «10 хомутов»:
   Уточните: хомут для дренажа или для фреонопровода?

   [ #43 Хомут для крепления дренажа М8 25мм (шт) ]
   [ #44 Хомут для крепления фреонопровода М8 32 мм (шт) ]
   [ 🚫 Пропустить эту позицию ]
   ```
2. **«Протянули 100 м кабеля»**:
   В смете 6 вариантов кабелей (3х2,5, 3х1,5, 4х1,5, 3х4 и др.). Бот просит выбрать нужное сечение.

## 3. Что делать, если LLM ошиблась

Ни одна LLM не гарантирует 100% точности во всех краевых ситуациях. В нашей архитектуре предусмотрена **многоуровневая защита от ошибок (Error Recovery)**:

1. **Экран интерактивного подтверждения (Human-in-the-Loop)**:
   - Данные **никогда не пишутся в Google Sheets и Битрикс24 напрямую** без предварительного показа мастеру.
   - Мастер видит весь распознанный перечень с начисленной ЗП и единицами измерения.
2. **Инлайн-редактирование в один клик**:
   - `[✏️ Изменить объём]` — позволяет скорректировать цифру любого пункта без повторного ввода текста.
   - `[➕ Добавить]` — позволяет добавить работу, которую мастер забыл упомянуть или которую модель пропустила.
   - `[🗑 Удалить позицию]` — моментально убирает ошибочно распознанный пункт.
   - `[❌ Отменить всё]` — сбрасывает черновик.
3. **Исправление уже сохраненных данных за сегодня (`/today`)**:
   - Если мастер нажал «Подтвердить», а через час заметил ошибку, команда `/today` (или кнопка в меню) выводит все сегодняшние записи и позволяет обновить или обнулить любую ячейку в таблице.
4. **Резервный офлайн-парсер (Deterministic Fallback)**:
   - Если API LLM недоступен (таймаут сети, кончился баланс ключа), управление автоматически подхватывает локальный Regex/RapidFuzz анализатор, не роняя бота и гарантируя непрерывность рабочего процесса на стройплощадке.

## 4. Ограничения решения

1. **Неразборчивые аудиосообщения**:
   - При сильном шуме стройки (работа перфоратора, отбойника) Whisper может исказить фонетически похожие слова. Система нивелирует это показом распознанного текста перед сохранением (`🎙 Распознано: «...»`).
2. **Смешение нескольких дат в одном сообщении**:
   - Текущая версия записывает выполнение в столбец с **сегодняшней датой** (либо выбранной целевой). Если мастер скажет «вчера сделали 10 м, а сегодня 20 м», система потребует разбить это на два подтверждения либо явно указать дату.
3. **Лимиты Google Sheets API**:
   - Google имеет квоту в 60 запросов на запись в минуту. Для масштабирования на сотни объектов мы используем пакетное обновление (`batch_update`), потребляющее 1 запрос на весь отчет.

## 5. Памятка к техническому интервью (Live-coding & FAQ)

Возможные доработки на интервью и как они быстро реализуются:
1. **«Добавьте новую позицию в смету»**:
   Достаточно вставить строку в Google Sheets или Excel и нажать `/reload` в боте — позиция появится мгновенно без правок в коде!
2. **«Измените формат даты столбца»**:
   В `services/sheets_service.py` функция `get_or_create_date_column`: изменить `date_target.strftime("%d.%m.%Y")` на нужный шаблон.
3. **«Добавьте поле Приоритет/Проект в задачу Битрикс24»**:
   В `services/bitrix_service.py` метод `send_report`: в словарь `task_payload["fields"]` добавить `"PRIORITY": 2` или `"GROUP_ID": <id_проекта>`.
4. **«Добавьте валидацию минимального объема»**:
   В `services/llm_service.py` или `models/schemas.py`: добавить `Pydantic validator` на `volume > 0`.
